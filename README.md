# 听一句

“听一句”是一个本机循环朗读工具：输入正文后，Kokoro 会反复朗读当前段；只有你主动向前移动，才会切换内容。它同时提供适合普通抄写的“逐段”模式，以及保留上一个短句、连续向前推进的“跟写”模式。

## 启动

在 macOS 上双击 `启动听一句.command`。启动器会自动完成三件事：

1. 首次运行时，在 `~/Library/Caches/tingyiju/venv` 创建独立语音环境并安装依赖。
2. 准备 `Kokoro-82M-v1.1-zh`；首次朗读时从本机缓存载入，模型缺失时自动下载。
3. 启动只监听 `127.0.0.1:8765` 的服务并打开浏览器。

首次安装和首次载入模型会较慢；之后启动会直接复用环境和模型缓存。关闭启动器所在的终端窗口即可停止服务。不要直接双击 `index.html`，那样无法连接语音服务。

## 使用

1. 粘贴要抄写的正文；应用会先按句号、问号、感叹号和换行形成自然句，再按分号、逗号和冒号识别语义短句。
2. 选择“逐段”或“跟写”，设置每段的期望长度；默认软目标为 10–18 字。
3. 从四个固定 Kokoro 音色中选择一个：`zf_001`、`zf_004`、`zm_010`、`zm_025`。
4. 设置语速和重复间隔，点击“开始朗读”。
5. 写完当前内容后点击“下一段”或“向前一步”；最后一项会显示“完成”。

正文只在浏览器当前页面和本机服务之间传递，不会发送到外部语音平台。生成结果按“模型版本 + 音色 + 语速 + 文本”缓存在 `~/.cache/tingyiju/audio`；重复播放同一句会直接重放当前音频。

## 语义短句与自适应分段

切分和组合是两层独立规则：标点决定哪里可以切，目标长度只决定如何组合完整短句。

1. 句号、问号、感叹号和换行结束一个自然句；跟写模式会在这里重置重叠。
2. 分号是强停顿；逐段模式不会跨过分号合并。
3. 逗号和冒号形成普通语义短句；相邻短句可以根据目标长度重新组合。
4. 顿号不会默认拆开短枚举，只有整条短句过长时才作为备用边界。
5. 只有缺少可用标点且单条短句极长时，才会在中文词语或英文单词边界启用备用切分。

“期望最短”和“期望最长”都是软目标。为了保留自然语气，一个完整语义短句可以超过期望最长值；应用不会只为凑字数而硬切句子。

## 两种朗读方式

- **逐段**：先得到语义短句，再合并相邻的短句，使每段尽量接近期望长度。适合一句写完后手动切换。
- **跟写**：每一步朗读“上一条完整短句 + 一条新短句”。例如原文拆成 A、B、C、D 后，依次朗读 A+B、B+C、C+D；遇到新的自然句或换行后，从新句内部重新开始。界面中带下划线的淡色文字表示上一条短句。

跟写模式首版保持手动前移，不自动跳转。这样不会在书写尚未完成时抢先切换，也不会因为估算朗读时间而产生字符级硬切。

## 操作规则

- 朗读自然结束后，只等待设定间隔，再重复当前内容，不会自动推进。
- 前后移动会立即取消旧的下载、音频和等待任务。
- “暂停”会保留当前位置；“继续”从当前内容开头重新朗读。
- 修改文章会立即清除旧分句，需要重新开始。
- 修改朗读方式或目标长度会清除旧队列，需要重新开始。
- 页面切到后台会自动暂停，回到页面后需手动点击继续。
- 右方向键向前移动，左方向键向后移动，空格暂停或继续，Esc 结束；编辑输入框时不会触发快捷键。

## 本地验证

前端测试需要 Node.js 18 或更高版本：

```text
node --test test/*.test.js
```

服务端基础测试不依赖 Kokoro 运行环境：

```text
python3 -m unittest test/test_server.py
```

语音模型、依赖和生成缓存都位于本机，不产生云端调用费用。
